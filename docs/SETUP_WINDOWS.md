# Setting up choppa on Windows

Everything you need to run, edit, test and build the game on your own PC. Steps 1–3 are
enough to play from source; the rest is optional.

## 1. Install the tools

| Tool | Where | Notes |
|---|---|---|
| **Git for Windows** | https://git-scm.com/download/win | Defaults are fine. |
| **Godot 4.7.2** (standard, *not* .NET) | https://godotengine.org/download/archive/4.7.2-stable/ → "Windows 64-bit" | It's a zip, no installer. Unzip to e.g. `C:\Tools\Godot\`. You get `Godot_v4.7.2-stable_win64.exe` (editor) and `..._console.exe` (same, with a console window for logs and tests). |

Use exactly 4.7.2: the project and the CI builds are pinned to it.

Optional: add `C:\Tools\Godot` to your `PATH` so you can type the exe name in a terminal.

## 2. Get the code

In a terminal (PowerShell or Git Bash):

```powershell
cd C:\Projects
git clone https://github.com/agnorance/choppa.git
cd choppa
git checkout godot-foundation
```

`godot-foundation` is the branch Claude works on. Later, `git pull` fetches new work.

## 3. Open and play

1. Start `Godot_v4.7.2-stable_win64.exe`.
2. In the Project Manager click **Import**, pick `C:\Projects\choppa\project.godot`, then
   **Import & Edit**. The first import takes a minute (it builds the `.godot\` cache).
3. Press **F5** (or the ▶ button top right) to play.

Controls are in the README. Esc returns to the menu.

Run straight from a terminal without the editor:

```powershell
& "C:\Tools\Godot\Godot_v4.7.2-stable_win64.exe" --path C:\Projects\choppa
```

Game options go after `--`, e.g. jump straight into a battle on Mesa Basin:

```powershell
& "C:\Tools\Godot\Godot_v4.7.2-stable_win64.exe" --path . -- --mode=battle --map=basin
```

All options are listed at the top of `scripts/main.gd`.

## 4. Run the tests

```powershell
& "C:\Tools\Godot\Godot_v4.7.2-stable_win64_console.exe" --headless --fixed-fps 60 --path . --script res://tests/run_tests.gd
```

It prints `PASS`/`FAIL` per test and ends with `ALL TESTS PASSED`. After adding a script
with a new `class_name`, run `... --headless --path . --import` once first.

## 5. Build a Windows .exe yourself

1. In the editor: **Editor → Manage Export Templates → Download and Install** (once,
   ~1 GB).
2. **Project → Export…**, select **Windows**, **Export Project…**, save as
   `build\windows\choppa.exe`.

CI does the same on every push; see the Actions tab on GitHub.

## 6. Build the Android APK yourself (optional)

CI already builds the APK, so you only need this to build locally or deploy over USB.

1. Install **JDK 17** (e.g. Eclipse Temurin 17).
2. Install **Android Studio**, open **SDK Manager** and install: Android SDK Platform
   (API 35), Android SDK Build-Tools, Android SDK Platform-Tools, Android SDK
   Command-line Tools.
3. In Godot: **Editor → Editor Settings → Export → Android**: set *Java SDK Path*
   (e.g. `C:\Program Files\Eclipse Adoptium\jdk-17...`) and *Android SDK Path*
   (e.g. `C:\Users\<you>\AppData\Local\Android\Sdk`). Godot creates a debug keystore
   by itself.
4. **Project → Export…**, select **Android**, **Export Project…**.
5. With the phone on USB and developer mode / USB debugging on, the Android icon that
   appears next to ▶ in the editor installs and starts the game directly
   ("one-click deploy").

## 7. Regenerate textures and models with Blender (optional)

Textures in `assets/textures` and models in `assets/models` are generated by Python
scripts in `tools/blender/` and committed, so you only need this to change them.

1. Install **Python 3.13** (python.org; tick "Add to PATH").
2. `pip install bpy==5.2.2` (Blender as a Python module, ~400 MB).
3. Run the script for what you want to change:
   - `python tools/blender/make_textures.py` (or with names, e.g. `sandstone rock`)
   - `python tools/blender/make_rocks.py`: mesa, arches, hoodoos, boulders
   - `python tools/blender/make_choppa.py`: the helicopter (the scout)
   - `python tools/blender/make_airframes.py`: the gunship and the heavy
     (`--preview out_dir` renders Cycles previews instead of exporting)
   - `python tools/blender/make_cockpit.py`: the cockpit interior
   - `python tools/blender/make_trees.py`: the pines and their needle texture
     (`--preview out_dir` too)
4. Sounds don't need Blender: `pip install numpy`, then
   `python tools/audio/make_sounds.py` (or with names, e.g. `gun explosion`).

You can also open the results in the regular Blender 5.2 app.

## 8. Work on it with Claude Code

The repo is set up for Claude Code: `CLAUDE.md` holds the project rules and commands,
`.claude/skills/` has step-by-step guides (screenshots, Blender assets, new items, new
maps, shipping a change), `.claude/settings.json` pre-approves the everyday commands.

1. Install Claude Code (https://code.claude.com) and open a terminal in the repo.
2. Tell the helper scripts where Godot is, once per user:
   ```powershell
   [Environment]::SetEnvironmentVariable("GODOT", "C:\Tools\Godot\Godot_v4.7.2-stable_win64_console.exe", "User")
   ```
   (open a new terminal afterwards). Without it they try the PATH and `C:\Tools\Godot`.
3. If PowerShell refuses to run the scripts, allow local scripts once:
   `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
4. Start `claude` in the repo. Handy scripts it (and you) can use:
   - `tools\test.ps1`: import and run all tests.
   - `tools\run.ps1 --mode=battle --map=basin`: play with game arguments.
   - `tools\shot.ps1 out.png --cam=showcase --frames=150`: screenshot to a file.
5. For Blender work also do step 7 (Python 3.13 and `bpy`).

On your GPU screenshots take seconds, so effect timing (explosions, muzzle flashes)
is best checked here rather than in the cloud sessions.

## Graphics and your GPU

The game uses Godot's **Forward+** renderer on Windows (Vulkan or Direct3D 12) and the
**Mobile** renderer on Android. Machines without Vulkan fall back to the simpler
Compatibility renderer automatically, which looks flatter. Keep your GPU driver up to date.

## Troubleshooting

- **"Could not find type …" / parse errors after `git pull`:** close Godot, delete the
  `.godot\` folder in the project, open it again (it re-imports).
- **Black or pink materials:** the import didn't finish; wait for the progress bar at
  the bottom of the editor, or reimport (`--headless --import`).
- **Wrong Godot version warning:** use 4.7.2 exactly.
